# 2026-03-17 -- MVP and Delivery Direction

## Status

Accepted

## Decisions

- Start with a concrete fulfillment domain instead of a generic simulation platform.
- Build desktop-first, but introduce API support early.
- Keep desktop and API aligned on the same application-facing data contracts where practical.

## Reasoning

- The team needs a small, visual, demo-friendly MVP with clear business value.
- The desktop delivers the strongest MVP demo, while the API prepares shared contracts and future remote access.
- Shared contracts reduce duplication and keep the product surface consistent across delivery hosts.
